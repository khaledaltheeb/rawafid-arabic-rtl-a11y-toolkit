# Support

This project provides reusable open-source engineering primitives for Arabic/RTL, localization, accessibility, Unicode bidi handling, and direction-aware web UI behavior.

## Questions and usage problems

Before opening an issue:

1. Review `README.md`, `docs/API-CONTRACT.md`, `docs/COMPATIBILITY.md`, and `docs/RTL-TESTING.md`.
2. Reduce the problem to a minimal reproducible example.
3. Include runtime/browser versions, locale tag, script/direction context, and the expected versus observed behavior.

Use a public GitHub issue for reproducible, non-sensitive bugs and reusable feature proposals.

## Security reports

Do **not** publish exploit details, credentials, private data, or suspected supply-chain compromise in a public issue. Follow `SECURITY.md` and use GitHub private vulnerability reporting when enabled.

## Scope boundary

Support requests must not include Rawafid scientific/editorial content, private datasets, user data, production configuration, secrets, or proprietary publishing/content pipelines. `OPEN_SOURCE_SCOPE.md` is authoritative.

## Accessibility reports

For accessibility defects, include the relevant browser, operating system, assistive technology if applicable, interaction method, and a minimal reproduction. Automated axe results are useful evidence but are not a substitute for describing the actual user-impacting behavior.

## Localization and RTL reports

Include the complete BCP 47 locale tag (for example `ar-JO`, `ar-Latn`, or `az-Arab`) rather than only the language name. For bidi defects, provide a minimal plain-text reproduction and identify any explicit Unicode controls if known.
