# Localization QA SARIF interoperability

Rawafid emits its localization QA findings in two complementary machine-readable forms:

- `partner-results/localization-qa.json` is the project-native evidence report with contract metadata, locale counts, summary counts, findings, and non-claims.
- `partner-results/localization-qa.sarif` is a SARIF 2.1.0 interchange surface for external static-analysis, code-scanning, CI, and quality systems.

## Why SARIF

SARIF is the OASIS Static Analysis Results Interchange Format. GitHub code scanning supports SARIF 2.1.0 for third-party analysis results. The toolkit therefore exposes the localization QA findings in a standard analysis envelope instead of requiring every partner to write a Rawafid-specific parser.

## Mapping

Each localization QA check becomes a SARIF rule. Error findings map to SARIF `error`; informational context maps to `note`. Each finding retains:

- the rule/check identifier;
- locale and localization key;
- the human-readable finding message;
- the affected `locales/<locale>.json` artifact;
- the package version and localization contract identity at the run level.

The SARIF file is generated by `npm run localization:evidence` and independently checked by `npm run localization:sarif-check`. Both commands run in the mandatory core quality gate.

## Upload policy

The repository does **not** upload this SARIF file to GitHub code scanning by default. Generation and validation are vendor-neutral; upload is a separate integration decision because it can require additional permissions and can turn localization QA into repository alerts.

A partner may ingest the retained SARIF artifact directly, or a future provider-specific adapter may upload it after that integration is explicitly configured and observed.

## Evidence boundaries

SARIF transport does not change the meaning of the underlying checks. In particular:

- the output is not a linguistic quality score;
- zero-width findings remain contextual evidence, not maliciousness verdicts;
- markup-token parity remains a conservative structural check rather than an HTML parser or sanitizer;
- emitting valid SARIF does not imply GitHub, OASIS, Transifex, Weblate, or another provider has certified the toolkit.
