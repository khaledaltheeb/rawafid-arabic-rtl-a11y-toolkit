# Dependency lockfile policy

The repository now contains a committed npm lockfile generated by GitHub Actions on Node 24 with npm 11.17.0 from the exact reviewed `package.json` dependency set.

## Reproducibility contract

- `package-lock.json` is part of the reviewed source of truth.
- CI uses `npm ci`; it does not fall back to an unconstrained install.
- Docker verification uses `npm ci`.
- GitLab CI uses `npm ci`.
- The npm release workflow refuses publication without the committed lockfile.
- Direct development dependencies remain exact-versioned in `package.json`; transitive resolution is captured by lockfile version 3.

## Updating dependencies

Dependency changes should be made in a dedicated pull request. After changing `package.json`, regenerate the lockfile with the pinned/current supported npm toolchain, review the manifest and lockfile together, then run the complete quality and browser gates.

Dependabot is configured to group routine minor/patch development-tooling updates while blocking TypeScript major upgrades until the TypeScript/ESLint toolchain explicitly supports them. Security updates remain subject to GitHub's Dependabot security-update behavior.

## Audit expectations

Reviewers should inspect:

1. direct version changes;
2. unexpected transitive additions/removals;
3. license/provenance changes;
4. vulnerability findings;
5. install/build scripts introduced by dependencies;
6. package-manager and lockfile-version changes.

Do not hand-edit integrity hashes or fabricate lockfile entries.
